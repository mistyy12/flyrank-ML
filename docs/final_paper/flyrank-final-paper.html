Abstract

Website owners and content editors often manage a large number of content pages, making it difficult to determine which pages require review. This study investigates whether machine learning can prioritize pages at risk of future search impression decline more effectively than a rule-based baseline. Using Google Search Console (GSC) data from January–March 2026, Logistic Regression and a Shallow Decision Tree were evaluated against a rule-based baseline, with April 2026 reserved for outcome evaluation. The saved evaluation reports Precision@20 of 0.800 for logistic regression, 0.400 for the shallow decision tree, and 0.050 for the baseline, with a test-set base rate of 0.495. These preliminary results favor logistic regression for review prioritization, but require confirmation after checking missing outcome labels and rerunning the notebook; they do not establish that content interventions improve search performance.

1. Research question

This project focuses on Lane 2: Refresh / Content Opportunity Scoring, which aims to develop a machine learning-based ranking system that prioritizes content pages for human review. The prototype ranks pages for review and proposes an action-mapping framework to help website owners and content editors decide what to investigate. Editorial actions remain subject to human judgment.

The primary research question is:

Can a machine learning model prioritize pages that subsequently meet a search-impression decline label more effectively than a transparent rule-based baseline, as measured by Precision@20?

To evaluate this question, the project compares machine learning models against a fixed rule-based baseline. The baseline prioritizes pages using predefined conditions, including low click-through rate (CTR) and search impressions. In contrast, machine learning models combine multiple page-level features to estimate the likelihood of declining performance and rank pages accordingly.

The predictive usefulness of a search-performance signal may depend on other signals. For example, low CTR may have different implications at different levels of search exposure or average position. Learning feature weights or decision rules offers an alternative to assigning fixed points. This study tests that alternative using four historical GSC features; content age and time since update are not model inputs.

The modeling notebook produces ranked pages with decline scores. The recommendations section proposes how these rankings could support a human-reviewed action queue. Rather than automatically modifying or removing pages, the system is intended to support human decision-making by identifying pages that may benefit from further investigation.

Ranking performance is evaluated using Precision@20, the proportion of pages meeting the decline label among the 20 highest-ranked test pages.

2.1 Data Windows

The analysis uses two non-overlapping time windows:

Feature window: January 1 – March 31, 2026.

Outcome window: April 1 – April 30, 2026.

The feature window supplies historical page-performance measurements, while the outcome window is reserved for constructing the target label.

This separation ensures that future performance measurements are not directly included in model inputs when predicting subsequent decline.

2.2 Data Exclusions and Limitations

Records outside the January–April 2026 analysis period are excluded from the primary analysis.

Historical aggregation uses rows where GSC is available and both impressions and clicks are non-null. Unavailable measurements are excluded from these aggregates; GA4 is not used by the model. Differences in coverage may affect feature reliability and outcome labels.

2.3 Public Data Safety

The dataset is pseudonymized, and this research is intended to comply with FlyRank's data-use restrictions. This HTML paper contains no raw warehouse records, page identifiers, original page URLs, private queries, access credentials, or identifying mappings.

This paper presents aggregate evaluation metrics, model descriptions, methodological explanations, and suggested review actions. The final model and ranked recommendations are intended for research and human decision support, rather than automatic changes to client content.

3. Methodology

3.1 Research Assumptions

This study investigates whether historical Google Search Console (GSC) performance can be used to predict content pages at risk of future search visibility decline. The objective is to produce a ranked list of pages that may require further review, rather than automatically determine which pages should be refreshed.

The analysis assumes that historical search exposure, click-through rate (CTR), average search position, and data coverage provide useful signals for predicting future content performance.

The unit of analysis is an individual content page, uniquely identified by the combination of client_hash_id and content_hash_id.

3.2 Feature Engineering and Data Eligibility

Historical performance data from January 1 to March 31, 2026, is used to construct predictive features. April 1 to April 30, 2026, is reserved for outcome label construction and evaluation.

The machine learning models use four features:

Table 2. Model features
FeatureDefinition
valid_gsc_daysDistinct January–March dates with GSC available and non-null impressions and clicks
impressionsTotal January–March impressions across valid GSC rows
ctrTotal clicks divided by total impressions across valid January–March GSC rows
avg_positionSum of gsc_sum_position divided by impressions for valid rows with positive impressions, non-null position sums, and positive gsc_avg_position

CTR is calculated as:

CTR = Total Clicks / Total Impressions

Average search position is calculated as:

Average Position = Σ position sums / Σ corresponding impressions

To ensure sufficient historical observations, the following eligibility thresholds are applied:

Table 3. Historical eligibility criteria
CriterionMinimum requirement
Valid GSC days in feature window60 days
Valid GSC days in March20 days
January–March impressions500
March impressions100

The eligibility requirements include at least 60 valid GSC days during January–March, 20 valid days in March, 500 impressions during January–March, and 100 impressions in March.

Eligibility also requires non-missing CTR and average position. These conditions use historical observations only. April outcome availability must be checked separately when constructing labels; it is not a predictor or a historical eligibility threshold.

3.3 Target Label Definition

The target variable, is_declining_label, is a binary classification label designed to identify pages that experience a substantial decrease in search impressions between March and April 2026. For each month, impressions per day are calculated as total impressions on valid GSC rows divided by the number of distinct valid GSC dates. This is an average over observed valid days, not all calendar days.

A page is classified as declining when:

April Impressions per Day ≤ 0.80 × March Impressions per Day

Therefore:

Label = 1 (Declining): April average daily impressions are at least 20% lower than March average daily impressions.

Label = 0 (Not Declining): April average daily impressions remain above 80% of March average daily impressions.

The 20% decline threshold is an initial operational assumption. It does not establish that the page requires refreshing, nor does it imply that a content intervention would reverse the observed decline.

The intended evaluation requires an observable April outcome. However, the reviewed notebook does not explicitly filter missing April daily-impression values before applying the comparison and converting it to an integer label. With the float-valued data shown in the notebook, a missing value can therefore receive label 0. The affected count is not reported. This must be checked and, where necessary, corrected before treating the reported scores as final. No 20-day April eligibility requirement is used.

3.4 Rule-Based Baseline

A rule-based scoring system is used as the baseline against which machine learning performance is evaluated.

The baseline prioritizes pages with substantial search exposure but relatively low click-through rates. It assigns points according to predefined conditions rather than learning weights from historical examples.

The scoring rules are:

Table 4. Baseline scoring rules
ConditionScoreReason code
At least 500 impressions and CTR below 1%+2high_exposure_low_ctr
Meets the preceding condition and has average search position between 1 and 10+1good_position_low_ctr
Does not satisfy minimum valid-history requirementsUnscoredinsufficient_history

Pages are ranked by their total score in descending order. When multiple pages receive the same score, historical impressions are used as a descending tie-breaker, followed by ascending client and content identifiers to resolve remaining ties.

Eligible pages that do not meet the low-CTR condition receive score 0. Pages with insufficient history or missing average position are excluded from the common evaluation population, so they do not appear in the evaluated rankings.

The baseline is intentionally interpretable: each ranking decision can be traced to an explicit condition and its associated reason code.

April performance measurements are excluded from baseline scoring and used only for determining the observed outcome.

3.5 Model Training and Validation Design

Two supervised machine learning models are evaluated: logistic regression and a shallow decision tree. Their ranking performance is compared against the rule-based baseline.

Logistic regression estimates a decline-class probability and uses median imputation followed by standardization, with max_iter=1000 and random_state=42. The decision tree uses median imputation, max_depth=3, min_samples_leaf=20, and random_state=42. Both pipelines are fitted on training data only. Model probabilities are used as ranking scores; probability calibration is not evaluated.

The target variable is is_declining_label.

A single GroupShuffleSplit uses client_hash_id, test_size=0.20, and random_state=42. The 20% test proportion applies to client groups, not pages. The saved split output reports 35,721 training pages from 20 clients and 21,377 test pages from 5 clients, with no shared clients. These counts describe the saved run and may change after correcting outcome-label handling.

Model preprocessing parameters are fitted exclusively on the training partition. A fixed random seed is used to make the experiment reproducible.

The primary metric is Precision@20: the proportion of pages labeled declining among the 20 highest-ranked pages pooled across all held-out clients. Precision@50 is secondary. This is a pooled ranking evaluation, not an average of per-client metrics.

Precision@20 = Number of Declining Pages in Top 20 / 20

The baseline and both models rank the same test population using the same target label. Models rank by predicted decline probability descending, then impressions descending, then client and content identifiers ascending. The same secondary tie-breakers are used for the baseline.

The evaluation also considers the proportion of declining pages in the test dataset, providing context for interpreting the ranking results.

The resulting scores indicate how effectively each method prioritizes pages that subsequently experience impression decline, rather than how accurately it estimates the causal benefits of content changes.

3.6 Data Validation and Leakage Prevention

Several data integrity checks and leakage safeguards are incorporated into the analysis.

Data Integrity Checks

The w05_model.ipynb notebook includes duplicate checks to determine whether individual content pages appear more than once within the final modeling dataset.

The checks found no duplicated client–content identifier pairs, confirming that each (client_hash_id, content_hash_id) combination uniquely identifies a row in the checked modeling dataset.

Additional schema validation checks were performed to ensure that required columns were present, including page identifiers, predictive features, and the target label.

Leakage Prevention

Four methodological safeguards are used to reduce the risk of data leakage.

1. Temporal separation

Predictive features are constructed using January–March 2026 observations. April measurements are reserved for determining the outcome label and are not included in the supervised models' feature matrix.

2. Client-grouped splitting

Training and test partitions are separated by client_hash_id, reducing the risk that the model learns client-specific patterns from clients also represented in the test set.

3. Training-only preprocessing

Preprocessing parameters are fitted exclusively on the training partition before transforming held-out observations. This prevents held-out feature distributions from directly influencing fitted preprocessing parameters.

4. Exclusion of outcome-derived information

The label, April performance metrics, grouping identifiers, and baseline scoring outputs are excluded from the supervised models' predictive features.

These safeguards reduce leakage risk by separating historical features from future outcomes and ensuring client-independent evaluation. However, incomplete April measurements and potential model-selection bias remain limitations.

4.2 Interpretation & Implications

In the saved evaluation, logistic regression ranked 16 pages labeled declining in its top 20 and 41 in its top 50. Its reported Precision@20 exceeded the rule-based baseline by 75 percentage points and the rounded test-set base rate by 30.5 percentage points. The top 20 included four pages labeled non-declining, illustrating that a high ranking is not a confirmed diagnosis.

In contrast, the Shallow Decision Tree performed below the test-set base rate, while the Week-4 rule baseline performed substantially worse. The baseline was designed to identify high-exposure, low-CTR opportunities, while the evaluation label measures subsequent impression decline. Its lower ranking precision under this label does not establish that the rule is ineffective for every content-review objective. The tree also assigns tied probabilities to pages in the same leaf, making its top-k ordering sensitive to the stated tie-breakers.

Subject to validating outcome labels and rerunning the evaluation, logistic regression is the leading candidate among the tested methods. However, the results do not establish that refreshing the identified pages would improve their performance. Further evaluation across different time periods is needed to assess generalizability. Accordingly, the proposed system is intended as a decision-support tool for human content reviewers rather than an automated content optimization mechanism.

5. Limitations

5.1 Methodological Limitations

This study evaluates a predictive ranking system rather than the causal effectiveness of content optimization.

The analysis uses January–March 2026 as the feature window and April 2026 as the outcome period. Therefore, the model's performance across different time periods remains unverified.

Furthermore, the minimum GSC coverage and impression thresholds exclude pages with insufficient historical data or low search exposure. This may limit the model's generalizability to newer or lower-traffic pages.

The target label also relies on a predefined 20% impression-decline threshold, which creates a sharp distinction between pages with otherwise similar performance changes. For example, a 19% decline is classified differently from a 21% decline.

Only one client-grouped split is reported. Pooled top-k results can be dominated by a small number of clients, and the paper does not report per-client performance, repeated-split variation, or confidence intervals. Each changed label in the top 20 changes Precision@20 by five percentage points. Selecting a preferred model from this same test comparison also means the score is not an independent estimate for a previously selected model.

Missing April outcomes are not explicitly excluded in the reviewed labeling code. Even after that is corrected, averages based on few valid April days can be unstable or unrepresentative of the full month. Coverage-sensitive evaluation is therefore needed. In addition, inconsistent saved diagnostic outputs prevent treating the notebook as evidence of one clean end-to-end execution.

5.2 Scope of claims

The saved comparison reports higher Precision@20 and Precision@50 for logistic regression than for the evaluated baseline and decision tree. These are preliminary descriptive results; no statistical significance or performance on future periods is established.

However, the results do not establish why individual pages declined, reveal Google's search ranking algorithm, or prove that refreshing, expanding, or pruning recommended content would improve its performance.

Accordingly, the model should be interpreted as a decision-support tool for prioritizing human content review, rather than an automated system that guarantees successful content optimization.

6. Recommendations

6.1 Proposed Review Actions and Reason Codes

The Logistic Regression model ranks eligible content pages by their predicted probability of impression decline. Pages with higher scores are prioritized for human review. The table below proposes diagnostic actions based on observable signals; it does not document an implemented action-assignment pipeline or validated score thresholds.

“High decline risk” refers to review priority within the ranking rather than a calibrated probability cutoff. “Low CTR” uses the baseline reference of CTR below 1%. Pages failing historical eligibility require a separate data-quality review rather than a model score. These recommendations are diagnostic suggestions rather than confirmed solutions. A high decline score indicates review priority, not proof that content modifications will improve performance.

6.2 Human Review and Decision-Making

The proposed system is intended for content editors and page owners. Before taking action, reviewers should verify data availability, investigate seasonal or technical factors, and assess the page's content quality and business relevance.

Reviewers may approve, modify, or reject the suggested action based on their findings. The system should not automatically publish edits, delete pages, or modify indexing settings without human approval.

6.3 Monitoring and Retraining

If deployed, the system should be monitored periodically for changes in data quality, feature distributions, and prediction performance.

Precision@20 should be re-evaluated after subsequent outcome periods using the same label definition and compared against the rule-based baseline. Performance falling below the baseline for two consecutive periods would trigger a model review.

Retraining should only be considered after investigating potential data-quality issues or changes in content performance patterns. These monitoring procedures remain proposed safeguards rather than implemented production features.

The model comparison reports Precision@20 and Precision@50 for Logistic Regression, the Shallow Decision Tree, and the rule-based baseline. The action-mapping table describes suggested review actions; it is not a page-level ranked queue.

7.2 Reproducibility

The linked repository contains the data-contract, baseline-scoring, modeling, and proposed action-playbook notebooks. The playbook includes policy text and reference export code; a working ranked-action export is not established by the reviewed notebook.

The reviewed modeling notebook contains the aggregation, eligibility rules, label construction, model pipelines, split definition, and saved comparison underlying the reported metrics. Its Hugging Face path does not pin a dataset revision, and this paper does not provide package versions or a completed independent rerun. Reproduction requires authorized dataset access, a recorded dataset revision and environment, and a clean top-to-bottom execution after resolving outcome-label handling.

The published artifacts should exclude private client information, authentication credentials, and sensitive warehouse records. The repository serves as the reference for implementation details and reproducibility.
